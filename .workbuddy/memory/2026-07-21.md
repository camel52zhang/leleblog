## 修复：数据备份页"上传并恢复"报"恢复失败，请检查文件格式"
- 现象：后台 /admin/backup 点「上传并恢复」报错 `localhost 显示 恢复失败，请检查文件格式`。
- 根因（双层）：① 后端 `restoreBackup`（`backend/backup.go`）用 `os.Rename(tmpFile, dbPath)` 替换库文件；临时文件在 `os.TempDir()`（`/tmp`，容器内常是独立 tmpfs 挂载），`dbPath=/data/leleblog.db` 在卷 `/data`，**跨文件系统 rename 报 EXDEV 失败** → 500「无法替换数据库文件」。② 更致命：`restoreBackup` 一上来 `sqlDB.Close()` 关全局连接，失败后没重开 → 全局 `db` 永久停在关闭态，之后连 /api/health 都报 `db_unavailable`、导出也失败，只能重启 api 恢复。前端又把任何非 2xx 笼统显示成"请检查文件格式"，吞了真实原因。
- 修复 `backend/backup.go`：
  1. 新增 `siblingTemp(dbPath, prefix)`：临时文件生成在 `dbPath` 同目录（同文件系统），不在 `/tmp`。
  2. 用 `copyFile`（read+write 覆盖）代替 `os.Rename`，跨设备/文件被映射都安全。
  3. 恢复前先 `copyFile(dbPath, pre_restore)` 预备份；任何失败路径都 `copyFile(pre_restore, dbPath)` 回滚 + `reopenDB(dbPath)` 重开全局连接，保证 API 不瘫痪。
  4. 错误信息带底层 `err`（如 `恢复失败：写入数据库文件失败 - <err>`）。
  - 前端 `frontend/app/admin/backup/page.tsx`：恢复失败/成功把**后端真实 error 文案**透出（不再笼统"请检查文件格式"）。
- 构建与验证：前端 `tsc --noEmit` 通过；`docker compose build leleblog-api` + `leleblog-web`（CGO 编译，含镜像 `camel52zhang/leleblog-*:latest` 11:33:30 构建完成）；`up -d --force-recreate` 两容器重建于 11:53:26（晚于镜像）。
